## UI 规范

- 涉及页面、组件、样式或交互的任务，先读取并遵守 `ui-interaction-guidelines` Skill。路径：`<Skill 的本地路径>/SKILL.md`。
- 本项目平台：<只做桌面 / 只做移动 / 响应式，768px 切换>。
- 本项目组件库：<组件库名称>。下拉、弹窗、抽屉、日期选择、Tooltip 等复杂组件先用它实现。实现不了时，征得同意后引入单独的轻量组件。禁止自己编写滚动锁定、焦点管理和浮层定位代码。
- 同类控件只实现一次，放在 `<components 目录>`。页面只负责组合。新增控件前先检查是否已有同类组件。

### 最重要的 7 条（没有读取 Skill 时也必须遵守）

以下规则约束新写和本次修改的代码。已有代码不符合时，列出问题，经同意后再修改。

1. 操作成功后只更新受影响的区域，禁止为了更新数据而整页刷新。筛选、分页、滚动位置和已填写的内容保持原样。
2. 禁止点击后在原位置插入表单或面板、把下方内容挤走。改用抽屉、弹窗或独立页面。
3. 每个区域只有一个主操作。表格操作列最多直接展示 2 个按钮，其余放进「更多」。
4. 异步操作有加载、成功、失败三种反馈。点击后在逻辑上防重复：操作进行中时忽略后续点击。
5. 移动端按 Skill 中的形态对照表改变组件形态，禁止把桌面布局直接缩小。
6. 移动端禁止页面缩放：输入框聚焦不放大，双击不放大，双指不缩放。图片预览、地图等特定区域由组件在区域内实现缩放。
7. 所有可点击元素都有交互反馈：桌面端有悬停和按下状态，移动端每次触摸都有按下反馈。点击后跳转或打开弹层时，界面立即有可见的变化。

## 写作风格

适用于回复、文档、代码注释和界面文案。

- 一句话只讲一个结论。直接说做什么。
- 不主动补充例外、边界和免责说明。我需要时会问。
- 禁用句式：「可以…但不…」「…也不…」「不是…而是…」「…而非…」「并非…」「不代表…」「不等于…」「兼顾…与…」。
- 写完检查一遍。出现上述句式时，拆成短句或删掉否定部分。

示例：
- 差：可以使用开关，但不要因为只有两个选项就机械使用，也不要用于语义不清晰的场景。
- 好：开启 / 关闭类设置用开关。

## 交付前检查

- 修改了界面时，按 Skill 第九节输出验收清单。
- 修改了文档或界面文案时，运行下面的命令。有命中就改写，误报可以保留：

```bash
rg -n "但不|也不|而非|并非|不代表|不等于|不是[^，。]*而是" <docs 目录> <src 目录>
```
