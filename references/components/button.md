# 按钮 Button

## 通用
- 分为主要、次要、文字、危险四种。一个区域最多一个主要按钮。
- 文案用动词开头，写明结果，如「保存」「删除订单」「创建订单」。确认框以外，避免只写「确定」「提交」。
- 触发异步操作时进入加载态：显示加载图标，宽度保持不变。操作结束后恢复，成功和失败都要恢复。
- 禁用状态明显可辨。用户无法判断禁用原因时，在旁边或 Tooltip 中说明。
- 禁用的按钮不触发悬停和聚焦事件。用 Tooltip 说明禁用原因时，Tooltip 挂在包裹按钮的元素上，包裹元素可以用键盘聚焦。
- 危险操作按钮使用危险色。它不作为默认焦点。
- 仅图标的按钮必须有 `aria-label`。桌面端再加 Tooltip。

## 尺寸
- 按钮尺寸分为几档（如小、中、大），每档的高度、内边距、字号、圆角都用统一变量定义。全项目只用这几档。
- 显式设置高度（或最小高度）、内边距、字号、行高、圆角。禁止依赖浏览器默认值，否则各平台显示的大小和形状不一致。
- 尺寸用 `px` 或 `rem`。禁止用 `vw` 等随屏幕宽度变化的单位定义按钮尺寸。
- 同一行的按钮和输入框高度一致。

## 状态样式
- 默认、悬停、按下、键盘焦点、禁用、加载六种状态都要定义样式。
- 各状态在同一色系内变化：按下比默认略深或略浅，禁用降低对比度。禁止某个状态变成另一种颜色。
- 每种状态下，文字和背景的对比度都要足够，按钮始终能认出来。
- 松开后回到默认样式。点击后禁止残留悬停色或焦点框。
- 悬停样式写在 `@media (hover: hover)` 里。触屏设备上点击后悬停样式会一直残留。
- 焦点框用 `:focus-visible`，只在键盘操作时显示。鼠标和手指点击后不显示焦点框。
- 用 `<a>` 做成的按钮，`:visited` 样式和默认一致，避免访问后变色。

## 防重复点击
- 点击后会发请求、跳转页面或改数据的按钮，都要防重复点击。
- 在逻辑上拦截：操作进行中时，后续点击直接忽略。只改样式、不拦截逻辑，算未完成。
- 点击后立即进入加载或禁用状态，用户能看到已经点上了。
- 操作结束后恢复可点击，成功和失败都要恢复。
- 支付、提交订单等不能重复执行的操作，同时要求接口支持幂等（如携带唯一请求编号）。

## 桌面
- 键盘焦点清晰可见。
- 按钮组的顺序全项目一致，主按钮固定在同一侧。

## 移动
- 触控区域至少 44×44px。
- 页面主操作可以固定在底部，并适配 iOS 底部安全区。
- 每次点击都有明显的按下反馈。iOS 上的处理见 `references/setup/base-styles.md` 的「跨平台控件外观」。

## 常见错误
- 一排多个同样式按钮，看不出主次。
- 加载时按钮宽度变化，带动周围布局跳动。
- 提交失败后按钮一直停在加载或禁用状态。
- iOS 上按钮变成系统默认的小圆角样式，和桌面端外观不一致。
- 手机上点击后按钮停留在悬停色，或者出现焦点框。
- 连续快速点击，提交了两次。
- 禁用按钮上的 Tooltip 永远不显示，用户不知道为什么不能点。
