# 模态弹窗 Modal

## 选择页面、抽屉还是弹窗
- **弹窗**：简短确认、6 个以内的字段、用户不需要参考背景内容。
- **抽屉**：查看详情、字段较多、需要对照页面内容。
- **独立页面**：内容复杂、步骤多、需要可分享的链接。

## 实现方式（按顺序选择）
背景滚动锁定和焦点管理交给组件库、引入的组件或浏览器原生能力完成，禁止自己堆防护代码。

1. **项目已有组件库**：使用它的 Dialog / Modal。它已经处理了滚动锁定、焦点和 iOS 兼容。禁止在外面再叠加一套滚动锁定。项目设置了 `scrollbar-gutter` 时，按 `references/setup/base-styles.md` 的「滚动条宽度」关掉组件库的滚动条补偿。
2. **已有组件实现不了**：按 `references/setup/component-sources.md` 引入一个单独的弹窗组件，引入前征得需求方同意。
3. **原生 `<dialog>`**：只在项目没有相关依赖、并且 Browserslist 中的浏览器全部满足 Chrome 105+、Safari 15.6+、Firefox 121+ 时使用。适合只支持新浏览器的管理后台。
   - 用 `showModal()` 打开。浏览器自动完成：背景无法点击和聚焦、焦点移入弹窗、按 Esc 关闭、关闭后焦点回到原来的元素。
   - 使用原生 `<dialog>` 时，背景滚动锁定只需要以下 CSS。其他两种方式由组件自己处理，禁止再加这段 CSS：

   ```css
   html:has(:modal) { overflow: hidden; }   /* 只在模态弹窗打开时锁定 */
   html { scrollbar-gutter: stable; }       /* 锁定时页面不横向跳动 */
   .modal-body { overflow-y: auto; overscroll-behavior: contain; }  /* 内容滚到底不带动背景 */
   ```

   - 需要点遮罩关闭时：内容放在内层容器中，点击目标是 `<dialog>` 本身时调用 `close()`。
   - 有未保存内容时：监听 `cancel` 事件，先确认再关闭。

以下做法在任何情况下都禁止。这里指你自己编写的代码，组件库内部的实现不受限制：
- 手写 `touchmove`、`wheel` 事件拦截来阻止背景滚动。
- 手写 Tab 键焦点循环。
- 逐个给背景元素加 `aria-hidden` 或 `tabindex="-1"`。
- 手写 `body { position: fixed; top: -滚动距离 }` 并在关闭时恢复。
- 自己用 `div` 加高 `z-index` 拼一个弹窗。

## 通用
- 提供明确的关闭方式：右上角关闭图标，以及「取消」按钮。
- 点击遮罩：纯展示类弹窗可以关闭。含表单的弹窗禁止点遮罩关闭，防止误触丢失内容。
- 打开后焦点移入弹窗。关闭后焦点回到触发按钮。
- 锁定背景滚动。关闭后恢复原来的滚动位置。
- 长内容固定头部和底部按钮，只滚动中间区域。整体高度限制在可视区域内。
- 切换内部 Tab 或步骤时，弹窗高度保持稳定。为内容区设定固定或最小高度。
- 底部按钮最多 3 个：一个主操作、一个取消，必要时加一个次要操作。
- 最多叠加两层：内容弹窗上再弹出确认框。
- 正在提交等不能中断的处理期间，可以暂时禁用关闭，并在弹窗内说明原因。处理失败或超时后恢复关闭。

## 桌面
- 按 Esc 关闭。
- 宽度按内容分为小、中、大几档，避免全部撑满屏幕。

## 移动
- 改用底部面板。内容多时改用全屏页，顶部提供返回或关闭。确认框按 `confirm.md` 处理。
- 软键盘弹出后，输入框和底部按钮保持可见。
- 适配 iOS 底部安全区。
- 高度用动态视口单位计算，禁止写死超出视口的高度。
- 按系统返回键或浏览器返回时，先关闭弹层，页面保持不动。弹层打开时用 `history.pushState` 加一条记录，监听 `popstate` 关闭弹层。用按钮关闭时，同步回退这条记录。小程序和 App 使用各自的返回拦截能力。
- 有未保存内容时，按返回键同样先确认。

## 常见错误
- 弹窗高度超出屏幕，底部按钮看不到。
- 弹窗打开后，滚动鼠标或滑动屏幕时背景页面跟着滚动。
- 打开弹窗、抽屉或下拉时，整个页面向左跳动一下，右侧露出一条空白。
- 弹窗打开后按 Tab 键，焦点跑到背景页面。
- 为了锁定滚动和焦点，写了大量事件监听代码，还和组件库自带的锁定互相冲突。
- 填了一半的表单，点遮罩后全部丢失。
- 移动端打开弹层后按返回键，整个页面退回上一页。
